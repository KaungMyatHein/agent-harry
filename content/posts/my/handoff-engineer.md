ဒီလို "အမြန်မေးခွန်းတွေ" က Developer ဆီကနေ ပေါ်လာတိုင်း မင်းရဲ့ handoff doc မှာ အပေါက်ကြီးတွေ ပွင့်နေတာပဲ။ ပြီးတော့ ည၆နာရီမှ ပြန်ဖြေနေရတယ်ပေါ့။ 📐

✦ ဒါက ဘာလဲ
handoff-engineer က မင်းရဲ့ ဒီဇိုင်းတွေကို developer တွေ တည်ဆောက်လို့ရအောင် ပြင်ဆင်ပေးတာ။ ဘာမှ ပြန်မေးစရာမလိုဘဲ တည်ဆောက်လို့ရတဲ့ spec ကို ရေးပေးတယ်လေ။ developer တွေ တကယ်ဘာလိုလဲဆိုတာကို သိတဲ့၊ ကိုယ်တိုင် code ရေးတတ်တဲ့ designer တစ်ယောက်ပေါ့။

✦ ဘယ်အချိန် သုံးရမလဲ
မင်း ဒီဇိုင်းတွေကို engineering ဆီကို လွှဲပြောင်းတော့မယ်၊ တည်ဆောက်လို့ရတဲ့ spec လိုအပ်နေပြီဆိုရင် သုံးရမှာ။ ဒါမှမဟုတ် ticket တွေ မလုပ်ခင်မှာပဲ edge case တွေကို ဖော်ပြပြီး accessibility ကိုလည်း အမှတ်အသားလုပ်ထားချင်တယ်ဆိုရင်ပေါ့။

✦ ဘာလို့ သုံးသင့်တာလဲ
ဒါမျိုးမရှိဘူးဆိုရင်လေ၊ ပုံမှန် case တွေနဲ့ ကြားထဲက အကွက်တွေက တည်ဆောက်ချိန်၊ bug တွေ၊ ပြီးတော့ ည၆နာရီမှ ပေါ်လာတဲ့ မေးခွန်းတွေ ဖြစ်ကုန်မှာပေါ့။ design token တွေကို document လုပ်ပေးတယ်၊ component contract တွေကို သတ်မှတ်ပေးတယ်၊ edge case တွေကို ဖော်ပြတယ်၊ accessibility ကိုလည်း အမှတ်အသားလုပ်ပေးတယ် — မေးခွန်းတွေ မပေါ်ခင်ကတည်းက ဖြေပေးထားတာလေ။

✦ ဘယ်လို သုံးရမလဲ
