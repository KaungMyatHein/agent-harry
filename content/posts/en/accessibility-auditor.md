An accessibility "opinion" feels responsible right up until the lawsuit, the complaint, or the user who simply can't get in. ♿

✦ What it is
accessibility-auditor audits a built prototype or live URL for WCAG 2.2 AA conformance by driving a real browser and running axe-core in-page — it measures, it does not guess.

✦ When to use it
A prototype or live URL needs a WCAG 2.2 AA audit grounded in real measurement. Or you only have an existing report or static markup/CSS to re-audit (Mode B).

✦ Why use it
Without it, accessibility is someone's best guess until it fails in production. An axe-core reading beats an opinion every time: deterministic findings across contrast, alt text, form labels, ARIA correctness, heading order, and keyboard reachability.

✦ How to use it
Just tell Agent Harry:
"Use the accessibility-auditor agent to run axe-core against the prototype and report WCAG 2.2 AA findings."

✦ Benefits
- Real browser run with axe-core in-page — deterministic, measured findings
- Full WCAG 2.2 AA coverage: contrast, alt text, labels, ARIA, headings, keyboard
- Mode B re-audits an existing report or static markup/CSS when there's no live page
