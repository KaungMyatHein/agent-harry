# Product Positioner

> The agent that turns research into a clear positioning statement — who it's for, what it does, how it's different.

## What it does

Takes Discovery output + (optionally) competitive analysis, produces a positioning statement using JTBD or "For X who Y, our Z is..." templates. Outputs the statement plus 3-5 value-prop bullets and a narrative paragraph.

## When to use it

- After Discovery is done, before features are prioritized.
- When the team's elevator pitch keeps changing — you need a written reference.
- Before [`pm-launch-architect`](pm-launch-architect.html) — positioning shapes the GTM story.

## When NOT to use it

- You're early in Discovery and don't have a clear problem yet.
- You're iterating on existing positioning → use Mode B to audit instead.

## What it asks you at intake

- Mode A or Mode B?
- Mode A: target user segment, primary problem, what category you're competing in.
- Mode B: paste existing positioning doc.

## What you get back

A handoff with the positioning statement, value props, narrative paragraph, and rationale for each choice (with evidence pointers back to Discovery).

## Best practices

- **Name a specific segment.** "SMBs" is too broad. "SMBs with 5-50 employees in the US healthcare vertical" is positionable.
- **Differentiation must be defensible.** "We're easier to use" isn't. "We're the only one that integrates with X" is.

## Common mistakes

- Vague target user.
- Differentiation that competitors could trivially copy.
- Forgetting to ground claims in evidence from Discovery.

## Costs and time

~$0.30-0.50

## What runs before / after

```
discovery-researcher → competitive-analyst → product-positioner → feature-prioritizer
```
