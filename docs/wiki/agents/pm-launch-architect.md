# PM Launch Architect

> The agent that turns a positioned product into a launch plan — beachhead segment, ideal customer profile, channels, messaging, battlecard, growth loops.

## What it does

Takes positioning + (optional) competitive analysis and produces a GTM plan: who you target first (beachhead), how you describe them (ICP), what channels reach them, what message lands, how you handle competitive objections (battlecard), and how the product grows post-launch (growth loops).

## When to use it

- After positioning is locked, before launch.
- For sales enablement (battlecard).
- When you need to pick which segment to focus first.

## When NOT to use it

- Positioning isn't done yet → use `product-positioner` first.
- Pre-launch validation focus → use `usability-tester` instead.

## What it asks you at intake

- Which output: beachhead+ICP, channel strategy, battlecard, growth loops, or full GTM?
- Target launch date.
- Existing GTM materials (if any) for Mode B audit.

## What you get back

Handoff with the chosen GTM artifact(s) + rationale + recommended sequence.

## Best practices

- **Beachhead before ICP.** ICP describes WHO; beachhead picks WHICH ICPs first.
- **Battlecard with real objections.** Don't make up competitor talking points.
- **Growth loops over funnels.** Loops compound; funnels don't.

## Common mistakes

- Trying to ship all GTM artifacts at once → ship beachhead+ICP first, the rest later.
- Generic messaging that doesn't differentiate.
